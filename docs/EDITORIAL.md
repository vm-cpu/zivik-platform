# Редакційний процес: ролі, перевірка перед публікацією, пошта

## Хто що може

Ролі EmDash (адмінка → **Users**):

| Роль | Рівень | Що може в НаСвітло |
|---|---|---|
| Contributor | 20 | писати чернетки своїх записів |
| Author | 30 | те саме + редагувати свої записи |
| Editor | 40 | редагувати **будь-які** записи, зберігати чернетки |
| Admin | 50 | усе, зокрема **публікувати**, схема, користувачі |

**Публікує лише адміністратор.** Плагін `site/emdash/review-policy.ts`
відхиляє «Опублікувати», «Зняти з публікації» й планування для всіх нижче
порогу з поясненням: «Збережіть чернетку й попросіть перевірити й
опублікувати». Поріг — змінна збірки `PUBLISH_MIN_ROLE` (Settings → Build →
Variables): не задана = `50`; `40` — дозволити публікувати й редакторам.

Рекомендований процес:

1. Редактор (роль **Editor**) вносить правку → **Зберегти**.
2. Якщо налаштовано staging (docs/STAGING.md) — за ~2 хв правку видно там.
3. Редактор пише адміністраторові: що змінено, посилання на запис.
4. Адміністратор перевіряє (ревізії запису показують різницю) → **Опублікувати**.
5. За ~2 хв правка на сайті.

## Пошта (вхід за посиланням, відновлення доступу, запрошення)

Без пошти EmDash не надсилає листів: вхід лише через passkey, загублений
passkey відновлює інший адміністратор, запрошення — посилання, яке треба
передати вручну. Плагін `site/emdash/email-resend.ts` надсилає листи через
[Resend](https://resend.com) (безкоштовний тариф із запасом).

Увімкнення:

1. Зареєструватися в Resend, **Domains → Add domain** — домен, з якого йтимуть
   листи (див. docs/LAUNCH.md про домен), додати DNS-записи, дочекатися
   «Verified».
2. **API Keys → Create** — права *Sending access*, лише цей домен.
3. Cloudflare → Worker `nasvitlo` → **Settings → Variables and Secrets**:
   - `RESEND_API_KEY` — тип **Secret**, ключ із кроку 2;
   - `EMAIL_FROM` — наприклад `НаСвітло <admin@ваш-домен>`.
4. **Settings → Build → Variables**: `EMAIL_PROVIDER` = `resend`.
5. Перезібрати (будь-яка публікація або Deployments → Retry). Після цього в
   адмінці з'являться «Увійти за посиланням», надсилання запрошень і
   відновлення доступу.

Перевірка: адмінка → Users → запросити себе на іншу адресу. Помилки — в
Observability (пошук `email not sent`).
